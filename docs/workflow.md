# 完整制作与复现流程

本项目采用独立实现的 HTML＋three.js 合成、Playwright/Chromium 逐帧采样和 FFmpeg 编码。5 秒样片中的 Pip、桌面、收件盘与卡片由代码生成，不需要模型下载，也不需要 Blender。声音由程序合成。

参考方法来自对 [onetake 案例](https://github.com/feitangyuan/onetake/blob/main/cases/clawd-desktop-19s/README.md)的分析；本项目没有复制其实现代码或素材。

## 一、先写可拍出来的创意

用一句话说明角色怎样改变物件：“Pip 依次踩中零散想法，将它们送入收件盘，收件盘展开成计划。”这句话同时规定主体、动作、结果和转场。

先明确五项约束：5 秒、16:9、120 BPM、一个连续空间、原创角色与界面。完整创作需求见 [样片提示词](sample-prompt.md)；参考片怎样被翻译成制作要求见 [重构提示词](reference-reconstruction-prompt.md)。

## 二、把故事拆成时间表

按每拍 0.5 秒建立节奏，再安排主要接触事件和停留。先让落地、归拢、展开、盖章各自可辨认，再调整时长。不要先铺满动画，最后才寻找音乐。

把视觉和声音使用的事件记录在同一份明确的时间表中。分镜、对象延续和验收标准见 [分镜文档](storyboard.md)。

## 三、程序化建模与搭景

1. 用圆角几何体建立 Pip 的身体、眼睛与脚；保持轮廓原创、简单易读。
2. 建立桌面、三片想法、杏色 Inbox 和 Plan 卡；为每个可动部分设置清楚的局部坐标。
3. 先用基础材质检查大小、位置、接触与遮挡，再加入高光、半透明和柔和阴影。
4. 将需要一起运动的部分放在共同的组节点中。角色脚下的承载物运动时，角色的位置也应按其局部锚点求值。

**可选的 Blender 路线**：当后续角色需要复杂曲面、骨骼或雕刻细节时，在 Blender 中制作原创模型，导出 glTF/GLB，由 three.js 的模型加载器导入。仍由同一绝对时间驱动片中动作。此路线是扩展方案，当前 5 秒样片未使用 Blender。

## 四、用绝对时间驱动动画

每个状态都由时间计算，例如 `角色位置 = 路径(t)`、`卡片折叠角 = 展开曲线(t)`、`文字长度 = 输入进度(t)`。主逻辑先设置对象状态，再设置摄影机，最后绘制。

关键原则：

- 定位到同一时间必须得到同一状态。
- 不用“上一帧位置加速度”作为离线渲染的唯一状态来源。
- 不在渲染路径中调用无种子的随机数。
- 将起跳、接触、回弹与声音共享的时间命名清楚。
- 字体和任何资源准备完成后，才允许截图。

这样既能在浏览器拖动时间检查，也能不按顺序渲染不同帧，避免播放速度或电脑性能改变成片。

## 五、镜头、灯光与材质

先用低位斜角建立 Pip、卡片和盘的相对位置。跳跃时小幅跟随；展开时升高、略后退；结尾减速稳定。摄影机运动要服务当前动作与结果，不要用持续旋转代替分镜。

材质的优先级为：形体清楚、接触清楚、文字清楚，然后才是反射、透射和景深。先看关键帧，再渲染视频，可以尽早发现画面越界、遮挡和倾斜文字难读等问题。

## 六、原创声音

为落地、卡片滑动、收件盘展开和最终盖章设计少量一致的音色。声音由程序合成并保留生成脚本，使发布内容可复现，也便于改动事件时间。音频输出后检查长度、峰值和听感，避免削波或过密。

```bash
python3 scripts/audio.py
```

安装依赖后可单独运行这条命令；`npm run render` 也会先生成声音。声音生成器输出 `assets/audio/sample.wav` 与 `assets/audio/sample.json`。0.25s 为入场落地，0.75/1.25/1.75s 为三次分拣，2.00/2.50s 为展开，3.00/3.25/3.50s 为计划行归位，4.15s 为最终盖章。详细材料和音量说明见 [原创声音设计](audio-notes.md)。

最终编码时将声音和画面一起合入 MP4；浏览器实时预览是否播放音频，以预览页实际功能为准。

## 七、安装与本地预览

需要 Node.js 与 npm、Python 3，以及可执行的 FFmpeg。首次安装浏览器运行时需要网络连接。Python 依赖用项目虚拟环境安装；JavaScript 依赖保存在项目中，Playwright 浏览器使用其缓存。

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
npm ci
npx playwright install chromium
python3 scripts/audio.py
npm run dev
```

以上激活命令适用于 macOS/Linux 的常见 shell；Windows 可使用 `.venv\Scripts\activate`。以后新开终端可重新激活虚拟环境；渲染器也会自动优先使用项目 `.venv` 中的 Python。`PYTHON=/path/to/python` 可显式指定。

打开终端显示的本地地址。预览用于检查动作和构图；交付视频以逐帧导出结果为准。

如果系统没有 FFmpeg，可通过系统包管理器安装，或按渲染脚本支持的方式指定本机 FFmpeg 可执行文件。不要把开发机的绝对路径写死为其他用户的唯一运行路径。

## 八、关键帧与渲染

```bash
npm run check
npm run stills
npm run render
```

`check` 运行项目自带检查；`stills` 生成几个关键时间的检查图；`render` 默认导出 5 秒样片。渲染过程为：启动本地页面 → 等待场景就绪 → 定位到第 n 帧的时间 → 截图 → 按顺序编码 → 合入原创音频。

若启用运动模糊，一帧需要在快门覆盖的短时间段内多次采样。应在光线性空间合成采样，避免直接模糊整张截图。运动模糊能改善快速动作的连续感，但不能修复错误路径或不合理接触。

## 九、检查交付物

- 视频为 5.000 秒、1920×1080、30fps、150 帧；音轨覆盖相同时间段。
- 检查开头、三次主要接触、展开中间态、盖章与最终停留，确认无穿帮、丢物体、闪白或浏览器错误。
- 以正常速度观看一次，静音观看一次，再单独听一次音轨。静音仍应能看懂因果。
- 检查三条计划行与完成勾在常见播放器尺寸下可辨认。
- 保留可复现的源代码、依赖锁文件、声音生成器、提示词、分镜和版本说明。

## 十、GitHub 发布与后续迭代

当前阶段交付 5 秒样片供审看。发布仓库时应包含源代码、构建与渲染命令、样片、关键帧、中文提示词和分镜；不要包含 `node_modules`、浏览器二进制、开发机缓存、用户原始参考视频或账号信息。

项目原创代码按仓库的 MIT 许可证发布；three.js、Playwright 等依赖保留各自许可证。参考来源说明创意分析的依据，不暗示作者参与本项目或提供了成片源码。

样片反馈应指出具体时间与问题，例如“2.3 秒展开太快”“最后计划卡看不清”。方向确认后，再依据拟议 20 秒分镜扩展剧情，更新事件表与声音，重新生成关键帧和成片。
